# QuizBuddy Tense Trainer

A vanilla JavaScript (ES Modules) tense recognition game for English learners. Practice past, present, and future tense forms across three difficulty levels.

**Live Demo:** not currently deployed. The previous Vercel URL
(`https://quiz-buddy-pp-ftense.vercel.app/`) returns `404 NOT_FOUND` on every
path; see [`docs/audit/SURGICAL-AUDIT-2026-10-21.md`](../docs/audit/SURGICAL-AUDIT-2026-10-21.md)
for the deployment finding and the `vercel.json` required to publish the
`QuizBuddyPPFtense/` subdirectory. Run it locally with the Quick Start below.

---

## Features

| Feature              | Description                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Three Levels**     | Easy (simple past/present/future), Medium (perfect/progressive), Advance (perfect progressive + conditionals) |
| **90 Questions**     | 40 Easy / 30 Medium / 20 Advance — no duplicates per level, each with a grammar insight                       |
| **Streak Scoring**   | +1 point per correct answer; +1 bonus every 3rd correct in a row                                              |
| **Grammar Insights** | Every answer reveals a short explanation of the tense used (pedagogical feedback)                             |
| **Review Mistakes**  | Wrong answers are recorded and can be replayed in a dedicated review mode                                     |
| **Tense Focus**      | Filter the question pool to past / present / future tenses                                                    |
| **Speed Run**        | 60-second timed mode with streak multipliers                                                                  |
| **Persistence**      | Scores & best streak saved to `localStorage` (survives browser close)                                         |
| **Accessibility**    | ARIA labels, live regions, focus management, keyboard navigable, high-contrast mode, reduced-motion support   |
| **Responsive**       | Stacks answer buttons vertically on mobile (< 540px)                                                          |
| **Offline PWA**      | Installable manifest + service worker, procedurally generated app icons                                       |
| **Zero Build**       | Pure ES modules — deploy static files anywhere                                                                |

## Quick Start

```bash
# Clone and enter project
cd QuizBuddyPPFtense

# Install dev dependencies (for lint/test/format)
npm ci

# Run tests
npm test

# Lint
npm run lint

# Format check
npm run format:check

# Serve locally (any static server)
npx serve .
# or
python3 -m http.server 8080
```

Open `http://localhost:8080` in a browser.

## Architecture

```
index.html
  └── js/app.js (entry)
        ├── js/state.js   ← single mutable state singleton
        │     └── localStorage (optional)
        ├── js/data.js    ← immutable QUESTIONS array
        └── css/style.css
```

- **No framework** — vanilla ES modules, `type="module"` in HTML
- **State** — single `state` object in `state.js` module scope; exposed via getters/setters
- **Persistence** — `localStorage` key `quizbuddy_scores_v1`; graceful degradation on quota/private-mode
- **Timers** — one `pendingAdvanceTimer` handle; cancelled on level change / reset to avoid stale callbacks

## Data Format (data.js)

Each question:

```js
{
  id: 'q_1',
  level: 'easy' | 'medium' | 'advance',
  sentence: 'I ___ to school every day.',
  options: ['walk', 'walked', 'will walk'],
  correct: 'walk',
  tenseCategory: 'past' | 'present' | 'future',
  explanation: 'Simple Present: describes a routine, habitual fact…'
}
```

Validation (via `data.test.js`):

- 90 total questions (40/30/20 split)
- Every question has 3 unique options
- `correct` is always one of the options
- No duplicate sentences within a level
- Every question carries a `tenseCategory` and a grammar `explanation`

## Accessibility Checklist

- [x] Semantic HTML (`main`, `section`, `article`, `header`, `footer`)
- [x] ARIA roles: `dialog`, `group`, live regions for score/streak and grammar insights
- [x] `aria-live="polite"` on game area for score/streak announcements
- [x] Focus management: start button → level buttons → answer buttons → change level
- [x] Visible `:focus-visible` ring on every interactive element
- [x] Color contrast (WCAG AA) via CSS custom properties — verified with axe-core (0 violations)
- [x] High-contrast theme toggle (persisted) for low-vision users
- [x] Reduced motion honoured (`prefers-reduced-motion` collapses spatial motion)
- [x] Keyboard operable (all interactive elements are `<button>`; 1/2/3 + A/B/C answer shortcuts)
- [x] 44 px minimum touch targets, hover affordances limited to real pointers

## Visual Engineering Notes

- Motion is compositor-only (`transform` / `opacity`); no animation touches
  `width`, `height`, `top`, `left`, `margin` or `padding`.
- Every live readout reserves its box (`tabular-nums` + measured minimum
  widths), so counters never reflow — cumulative layout shift stays ≈ 0.
- Buttons implement six tactile states: default, hover, active, focus-visible,
  loading and disabled.
